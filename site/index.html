TOON vs JSON

Token-Oriented Object Notation is a compact, line-based serialization built for feeding structured data to LLMs cheaply — same information, far fewer tokens.

Why TOON wins for LLM payloads

No repeated keys

JSON repeats every field name for every object. TOON declares the field header once per array, then streams rows — like CSV with types.

Fewer structural tokens

No { } [ ] " spam per field. Braces, quotes, and commas are the tokens that don't carry information — TOON strips them.

Explicit array length

TOON headers declare row count and columns up front (users[4]{id,name,role}), so the model — and validators — know the shape before reading data.

Cheaper at scale

Savings compound with array size: a 100-row JSON table pays the key tax 100 times. TOON pays it once.

Still typed

Unlike YAML-only savings, TOON keeps JSON's scalar types (numbers, booleans, strings) — no ambiguity for the model to guess at.

Lossless round-trip

TOON encodes/decodes back to the exact same JSON object — it's a transport optimization, not a data model change.
